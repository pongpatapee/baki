# 🥋 Baki

**A personal, offline-first workout tracker.**

> Named after *Baki the Grappler*, the anime about people who train to absurd extremes.

## Why

I liked Hevy's logging flow but never used the social side, and the features I actually wanted (unlimited routines, charts, custom exercises) were behind a subscription. So I built my own.

## Features

### 🏋️ Logging
- **Live workouts:** start empty or from a routine. Each row shows what you lifted last time in a **Previous** column, set types (warm-up / failure / drop), RPE, and supersets.
- **Crash-proof:** every tap is written to SQLite immediately. Kill the app mid-set and the workout resumes exactly where you left it.
- **Rest timer** starts automatically when you complete a set, with ±15s / skip, haptics, and a notification when the app is in the background.
- **Mini workout bar** so you can browse history or exercises without losing the workout.
- **Finish flow** discards unchecked sets and offers to update the routine with what you actually did.

### 📋 Routines
- **Unlimited routines and folders.** Duplicate, reorder, set per-set targets, rest times, and supersets.

### 📚 Exercises
- A curated library of 277 exercises using Hevy-style names (`Bench Press (Barbell)`), searchable and filterable by muscle and equipment.
- **Demonstration photos** for 226 of them (start/end position, crossfading like a short clip), bundled in the app so they work offline.
- **Custom exercises** with 7 tracking types: weight & reps, bodyweight, weighted bodyweight, assisted, duration, distance & duration, weight & distance.
- **Merge** duplicate exercises, and their history follows.

### 📈 Insights
- **Personal records** detected when you finish a workout: heaviest weight, best estimated 1RM, best set volume, most reps, longest duration or distance.
- **Per-exercise charts** for estimated 1RM, heaviest weight, set volume, session volume and reps over 1M / 3M / 1Y / All, plus a rep-max table.
- **Stats dashboard** with weekly volume, workout frequency, duration, muscle-group distribution and streaks.
- **Tools:** plate calculator and warm-up set generator.

### 💾 Your data
- **Import from Hevy:** load Hevy's CSV export, map exercise names, and import. Importing the same file twice won't create duplicates.
- **JSON backup and restore**, plus **CSV export** of every set.
- Android Auto Backup and iOS device backups include the database file.
- kg/lb, km/mi, and light/dark/system theme.

**Not included (on purpose):** social feed, followers, likes, accounts, cloud.

## Architecture

```
src/
├── app/                 # Expo Router screens (every file is a route)
│   ├── (tabs)/          # Workout · History · Exercises · Stats · Settings
│   ├── workout/         # live workout + post-workout summary
│   ├── routine/         # routine detail + builder
│   ├── exercise/        # exercise detail (charts, history, PRs) + editor
│   ├── history/         # workout detail + editing
│   ├── import/ tools/   # Hevy import wizard, plate & warm-up calculators
│   └── exercise-picker.tsx
├── db/
│   ├── schema.ts        # Drizzle schema (single source of truth)
│   ├── migrations/      # generated by drizzle-kit, bundled into the app
│   ├── repositories/    # the ONLY code that writes to the database
│   └── seed/            # bundled exercise library
├── domain/              # pure TS: units, volume, e1rm, PRs, stats, plates, warm-ups
├── import/ export/      # Hevy CSV parser, JSON backup, CSV export (pure TS)
├── stores/              # Zustand: rest timer, exercise picker contract, active workout
├── components/          # UI kit (ui.tsx) + feature components
└── theme/               # design tokens, light/dark, settings provider
```

**Design rules**
- **Screens stay thin.** Business logic lives in `src/domain` and `src/import`/`src/export` as pure TypeScript with no React Native imports, which keeps it fully unit-testable.
- **One write path.** Only `src/db/repositories/*` mutates data, and multi-row writes run in transactions.
- **Reactive reads.** Screens subscribe with Drizzle's `useLiveQuery`, so every list updates the moment data changes.

### Data model (sync-ready)

Baki is local-only today, but the schema is built so cloud sync (e.g. Supabase / PowerSync) can be added later **without a rewrite**:

- **UUIDv7 primary keys.** They're globally unique, so rows created on different devices never collide. Seeded exercises use stable `ex_*` slugs.
- **`created_at` / `updated_at` / `deleted_at`** on every row, in UTC epoch ms. That's enough for an `updated_at`-based push/pull with last-write-wins.
- **Soft deletes only**, so deletions can be synced.
- **Canonical units in storage** (kg, seconds, meters), converted only at the UI boundary.
- **Derived data is rebuildable.** `personal_records` can always be recomputed from sets.

```
routine_folders ─< routines ─< routine_exercises ─< routine_sets
                                     │
exercises ──────────────────────────┤
                                     │
workouts ─< workout_exercises ─< workout_sets
    └──────────────< personal_records (derived)
settings (key → JSON value)
```

## Getting started

**Prerequisites:** Node 20+, and either an Android device/emulator or an iPhone/simulator.
Baki uses native modules (Skia, SQLite), so it runs in a **development build**, not Expo Go.

```bash
git clone https://github.com/pongpatapee/baki.git
cd baki
npm install

# Local dev build (needs Xcode / Android Studio)
npx expo run:ios        # or
npx expo run:android

# …or build in the cloud with EAS, install it, then:
npm run build:dev
npx expo start --dev-client
```

### Installing on your phone & shipping updates

Baki ships to Android through the Play Console **internal testing** track (no review, updates in minutes), plus **EAS Update** for over-the-air JavaScript updates.

| Change | Command | Reaches the phone |
|---|---|---|
| JS/TS only (screens, logic, fixes) | `npm run update` | Next app launch (downloads on one launch, applies on the next), no store involved |
| Native (new native library, Expo SDK upgrade, permissions, icon, `app.json` plugins) | `npm run release:android` | Local build → uploaded to internal testing → Play Store update |

`runtimeVersion` uses the `fingerprint` policy, so an OTA update is only delivered to builds whose native code it is compatible with. If you run `npm run update` after a native change, the phone simply won't take it until you ship a new build. `fingerprint.config.js` excludes npm scripts and `.gitignore`, which don't affect native code.

**Why local builds:** the EAS free-tier Android worker (4 vCPU / 16 GB) kills the Gradle daemon while compiling Skia, Reanimated and Worklets. `eas build --local` uses the same EAS-managed signing key, so local and cloud builds are interchangeable.

**One-time setup**
1. Install the toolchain: `brew install openjdk@17 android-commandlinetools`, then with `sdkmanager` install `platform-tools`, `platforms;android-37.0`, `build-tools;37.0.0`, `ndk;27.1.12297006` and `cmake;3.22.1` into `~/Library/Android/sdk`.
2. Create the app in Play Console with package `com.wh1fty.baki`.
3. `npm run build:android:local`, then upload `build/baki.aab` manually to **Testing → Internal testing** (Google requires the first upload to be manual).
4. Add yourself under internal testing **Testers**, open the opt-in link on your phone, and install from the Play Store.
5. Create a Google Cloud service account with the Google Play Android Developer API enabled, invite its email in Play Console (**Users and permissions**, Baki, *Release apps to testing tracks*), and save its JSON key as `credentials/play-service-account.json` (gitignored). After that, `npm run release:android` uploads automatically.

**iOS:** needs an Apple Developer account. Use `eas build -p ios` then TestFlight; `npm run update` works for iOS builds too.

### Changing the schema

1. Edit `src/db/schema.ts`.
2. `npm run db:generate` creates a new SQL migration in `src/db/migrations/`.
3. The migration is bundled and applied automatically on next launch. Never edit generated migrations.

## Importing from Hevy

1. In Hevy, export your workout data as CSV (it's under **Settings**, in the export data section).
2. In Baki: **Settings → Import from Hevy** and pick the file.
3. Review the exercise mapping. Most names match the built-in library automatically, and anything unmatched can be mapped by hand or created as a custom exercise.
4. Import. Personal records are rebuilt from your full history.
